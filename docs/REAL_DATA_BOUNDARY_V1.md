# WORLD_MODEL_REAL_DATA_BOUNDARY_V1 — specification, trust requirements, evidence

Supersedes `REAL_DATA_BOUNDARY_V0.md` (kept for history). V0's HMAC
binding let the research account hold signing material; V0's production
entry point accepted caller-supplied key, root and commit overrides; V0
verified HEAD only; V0 reused output directories. All four are corrected.

## What a verified decision is

A JSON document under the admission root, **signed as a file** with
OpenSSH signatures (`ssh-keygen -Y sign`, namespace `apex-admission`) by a
principal listed in `allowed_signers`. The research path holds
`allowed_signers` (public keys) only. Issuance requires the private key,
which never exists on the research path; verification requires only the
public key. `ADMISSION_ISSUANCE: NONE` is recorded in every run's authority
stamp.

The decision binds: dataset identity and content (manifest sha256, per-file
sha256 at read), source families, fields (enforced at rebuild), universe,
temporal range, availability and corporate-action semantics with a named
`restricted_use` when publication/revision timing is NOT_AVAILABLE,
research purpose + experiment + registration hash, **code identity as
content** (`code.commit` = HEAD **and** `code.source_tree_sha256` = hash of
the tracked files under the relevant source paths, with those paths clean),
output root and authority classification, and provenance (principal, time,
review reference). The signer principal *is* `provenance.decided_by`.

## Entry points

| Function | Who calls it | Injection |
|---|---|---|
| `verify_decision(decision_path, *, experiment_id, registration_hash)` | production command | **none** — builds `production_trust()` from constants |
| `verify_decision_with(decision_path, trust: TrustConfig, ...)` | tests and audited callers | explicit `TrustConfig` |
| `scripts/alpha_exp_real_execute.py main(argv, *, trust=None)` | CLI (never passes `trust`) / tests | `trust` is a testing keyword only; asserted by test |

`TrustConfig` fields: `admission_root`, `allowed_signers`, `checkout_root`,
`permitted_roots`, `prohibited_roots`, `namespace`, `enforce_ownership`,
`ssh_keygen`, `relevant_source_paths`. No field converts a refusal into an
admission. Tests set `enforce_ownership=False` only because tmp files are
owned by the test user; the mode check is still enforced and tested.

## Filesystem and permission requirements (production)

| Path | Requirement | Verified by |
|---|---|---|
| `/etc/apex/admissions/` (admission root) | **every ancestor from `/` down** owned by a uid ≠ research uid and not group/other-writable (sticky dirs excepted); mode 0755 | `TRUST_PATH_OWNED_BY_RESEARCH`, `TRUST_PATH_WRITABLE`, naming the component |
| `/etc/apex/admissions/trust/allowed_signers` | same chain rule; 0644 | same |
| `/usr/bin/ssh-keygen` (verifier) | absolute path; executable, root-owned, ancestor chain root-owned; run with a fixed env and `cwd=/` | `VERIFIER_NOT_ABSOLUTE`, `VERIFIER_MISSING`, `VERIFIER_NOT_ROOT_OWNED`, `VERIFIER_PATH_WRITABLE` |
| execution checkout | dedicated; never `/opt/apex-repo`, `/opt/apex/current` or a release | `SHARED_CHECKOUT` |
| decision file and `.sig` | under admission root; 0644; not writable by research | same + `DECISION_OUTSIDE_ADMISSION_ROOT`, `UNSIGNED_DECISION` |
| signing key | **not on the host**, or at minimum unreadable by `apex`; never generated by engineering | out of band |
| output root (`/apex-data/research/…`) | writable by research; not under corpus/evidence/release/checkout roots | `OUTPUT_ROOT_INVALID` |
| checkout | relevant paths clean and equal to the decided tree | `SOURCE_DIRTY`, `CODE_IDENTITY_MISMATCH`, `SOURCE_IDENTITY_MISMATCH` |

**Present host state (measured, not compliant):** `/apex-data` is owned by the
research account, so the superseded admission root and everything beneath it
can be renamed away and replaced; `/etc/apex` does not exist; the research
account holds full passwordless sudo. The verifier refuses today with
`TRUST_PATH_MISSING: /etc/apex`. Evidence:
`results/si002_trust_path_audit.json`. Exact, unexecuted remedy:
`ADMISSION_OPERATOR_PACKAGE.md`.

Not protected against: arbitrary privileged code, or any account that can
become root — which, on this host today, includes the research account. The
ancestor and ownership checks are a boundary against ordinary replacement of
trust material by an unprivileged research account, and against nothing
stronger. Item 6 of the operator package (a separate non-sudo research
account) is what makes them meaningful.

## Runs

`open_run(grant, label)` creates
`<output_root>/<experiment>/runs/<UTC>-<label>-<8hex>` with `mkdir(exist_ok=False)`
and writes `_AUTHORITY.json` and `_RUN.json` with `O_EXCL` (never rewritten).
`_RUN.json` records decision sha256 and signer, manifest sha256, source
identity (commit, tree sha256, dirty list, checkout root) and runtime
provenance (executable, Python, cwd, pid, euid, every loaded `apex.*`
module's file). `seal_result` writes `_RESULT.json` exactly once.

Process outcomes of the command: `SCIENTIFIC_COMPLETE` (0; READY /
NO_OPPORTUNITY / NO_SIGNAL / EVALUATION_NO_SIGNAL / PLAN),
`AUTHORIZATION_REFUSED` (3), `EVALUATION_SEALED` (4; validation
SIGNAL_DETECTED, evaluation sealed — the expected first outcome of a
positive validation), `INVALID_INPUT_OR_FAILURE` (5; INVALID_INPUT,
INSUFFICIENT_EVIDENCE, execution error — sealed with traceback).

## Limitations

- Content commitment is per file; rows are not individually committed.
- `assumed_available` is a convention; it is labelled ASSUMED and the
  corpus' lack of publication timing is carried into the decision's
  `restricted_use`.
- Source binding covers `RELEVANT_SOURCE_PATHS` (world_model, chain
  ledger, sessions module, the command). The interpreter and third-party
  packages are recorded (runtime provenance) but not bound.
- Ownership enforcement relies on the host's uid separation; it is not a
  sandbox.
