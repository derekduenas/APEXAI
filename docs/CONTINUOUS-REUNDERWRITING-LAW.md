# APEX CONTINUOUS RE-UNDERWRITING LAW
## The Desk Never Falls In Love With Its Last Opinion

Sensors are continuous; state updates continuously; the Captain
re-underwrites on MATERIAL CHANGE or bounded HEARTBEAT. Every serious
candidate is a changing hypothesis carrying an OpportunityState
(DISCOVERED → WATCHING → DEVELOPING → SERIOUS → WAITING_FOR_ENTRY →
CAPITAL_REVIEW, with DEGRADED as a re-enterable detour). Only
INVALIDATED/EXPIRED are permanent — a dead thesis resurrects only as a
NEW candidate lineage.

Every re-underwrite asks: *"if this first appeared right now, knowing
only what is knowable right now, would we still care?"* — and answers
WHAT_CHANGED_SINCE_LAST_REVIEW as a computed diff, never a memory.
DIRECTION and ENTRY are separate axes: strong thesis + bad price =
WAITING_FOR_ENTRY, and a clean reset legitimately re-promotes.
TOO_EXTENDED / WAIT_FOR_RETEST / LIQUIDITY_POOR / WORLD_MIXED are
conditional waits, not deaths.

Anti-anchoring is structural: `reunderwrite()` accepts the prior STATE
LABEL only — no parameter exists through which prior conviction could
flow. Judgments carry AS_OF / review age / heartbeat limit and go STALE,
never silently current; attention scales with seriousness
(CAPITAL_REVIEW 60s → DISCOVERED 900s — operational routing, not alpha).
The board re-asks "is this still the BEST use of attention" every tick.
The morning thesis is a prior; when the tape contradicts it, THE BRIEF
LOSES. Constantly alert ≠ constantly trading: 4,000 observations and
zero trades can be a correct session.

NONE_FRONTIER_SHADOW throughout; Epoch-1 consumes none of it.
